A.2: Recover Homographies

To warp one image into the coordinate system of another, we need a homography matrix (denoted as H) to map the points from one image to another. We first collect 8 points using ginput and selecting 8 corresponding points (shown below). The last entry in our matrix is a 1 in order to retain the scale of the image. These are populated into A as the original points, and b represents the target coordinates. This is an overdetermined system due to the high quantity of points we are using, so least squares is used to average out the noise. By solving Ah = b, we can get the homography matrix that will map the original points (A) to the target points (b).

A.3: Warp the Images

To make a rectangular shape that has been warpped back to a rectangle, we can't just move pixels around since that would leave gaps in our display. Instead, we will use the inverse of the homography matrix we found before to see where it came from and sample the pixel value from the same source location. There are two interpolation methods we can use: nearest neighbor and bilinear. For nearest neighbor, the algorithm quickly rounds the source coordinate to the closest pixel (nearest neighbor). For bilinear interpolation, instead of just 1 pixel being chosen (the closest one), the 4 surrounding pixels are weighed based on how far from the target pixel and their values are scaled accordingly. As you can see, the nearest neighbor sampling makes straight lines more jagged since there is no smoothing factor that comes from averaging multiple pixels. This is extremely evident on the left side of the lamp box (image 1). When the inputs are blurry (like the projector screen), the differences are harder to catch.

A.4: Blend the Images into a Mosaic

To create the mosaic out of these individual images, we use the center image as reference and use the homography matrices to create projective transformations on the left and right images to match the details on the center one. By using alphas and weights, we are able to make the center of the image the strongest and have it fade on the edges as it connects to other images that would also provide details and context. The procedure goes like this:
  1. We find the matching points between the left and center images and the right and center images (using ginput).
  2. Compute the homographies for each pair using our algorithm from part A.2.
  3. Using the different matrices we get back and the 4 corners of each image, we figure out the maximum size of our output and set our output to this so we don't end up accidentally cropping, especially on the left since we use the center image as our center as well.
  4. Each image is inversed wrapped (part A.3) using bilinear interpolation, since this prevents the jagged edges that comes with nearest neighbor.
  5. Feathering, which uses a weighted average to remove seams, is implemented so each image does not have a hard seam at the edges. By weighing the edges less, the images can fade into each other creating a smooth mosaic.

Mosaic Set 1: Free Speech Movement Cafe

As you can see, the feathering causes ghosting, which is where we see double of some elements. To fix this, we use a 2 level Laplacian blend (similar to project 2). The low frequencies help give the color a smooth transition while the high frequencies are sampled from the image that has a larger weight on the pixel (usually means its closer to the center of the taken picture). Lastly, the normalization helps us not accidentally blend the black background we have on our output image.

B.1: Harris Corner Detection

Harris corners identify points on the image where the intensity changes drastically in multiple directions. By using the determinant and trace of the image gradients of a smoothed image, we are pinpoint areas of intensity variation. When the get_harris_corners() was ran, there were too many points that the image was crowded, so we eliminated less distinct features. As you can see, the points are around architectural details and textured regions. After getting a list of harris corners, adaptive non-maximal suppression (ANMS) selects a portion of the corners that would point to specific features. It also makes sure these features are properly spread out in order to describe the full image. One issue mentioned in the paper is that we don't want to only use strong harris corners since they are more likely than not to be concentrated in the same area. Using a suppression radius and a robustness constant of 0.9, we are able to spread the corners around a bit better. With ANMS, the points are highlighting specific details/features, like the windows and the cars, on the image while still being pretty spread out in order to get a good representation of the whole image.

Points Before and After ANMS

B.2: Feature Descriptor Extraction

With the ANMS corners selected, we now can find the feature descriptors needed to represent the image. To capture the broad structures and not get caught up on the specific details, the image is first greyscaled then Gaussian blurred. Each patch is a 40x40 window around an ANMS corner and every 5th pixel is selected to get the 40x40 window down to the target 8x8 patch. To make the descriptors less sensitive to brightness or contrast between overlapping photos, we had to do bias and gain normalization on the patches. Removing near-zero SD descriptors makes it so we won't have any numerical instability. From the features of the building, you can faintly make out portions of the trees, edges of the roof, and car details which does a good job summarizing the original image.

Feature and Descriptors

B.3: Feature Descriptor Extraction

Using the nearest neighbor ratio test, we are able to match points of overlapping photos. Using cdist, we can identify the descriptors that are the most similar because they should have the lowest feature-space distances. If the ratio of the closest and second closest match was below the selected ratio of 0.7, we can confidently believe that there are differences between a correct and incorrect match. This makes sure repetitive patterns and ambiguous matching does not happen. If it is a distinctive feature, it should only have one close match. The pairs are connected in green for ease of viewing and to see if the features are mapped properly. As you can see, there are some errors but the Lowe's nearest neighbor ratio test is helpful is removing the bulk of the ambiguities.

Feature Matches using the Lowe's Ratio Test

B.4: RANSAC for Robust Homography

By checking geometric transformation plausibility, we are able to match the corresponding points better than if we used similarities in appearance. First we choose 4 features (hence why it is called 4-point RANSAC), and use the compute_H function from part A to find the projective transformation matrix. 4 points equals 8 independent parameters of homography. After getting the H matrices, we need to classify the inliers now, which will tell us which points are supposed to be in the data set. We first check the errors between the source data point and the destination data point, then set an error threshold (e.g. 3). Using the homography with the most amount of inliers, aka most amount of accurate points to reconstruct, we are able to combine it with the mosaic function from part A as well and get the accurate panoramas. When compared to the manual selected mosiacing, it is definitely cleaner because it does not rely on a human choosing correct points and is not subject to human errors. For the cafe photo, I had to choose points again since there was some ghosting going on when I didn't choose the points as precisely. However, this RANSAC method is subjected to the quality of the detected features and descriptor matches.

Comparison between manual and automatic mosaicing

Another issue with the automatic mosaicing is that repeated patterns and curved features are hard to create descriptor matches for. To try to solve this, I added an if statement to reject collinear samples and degenerate 4-point samples. Even though it is a bit better, we can still see how these repeated curves make recreating the image hard.
